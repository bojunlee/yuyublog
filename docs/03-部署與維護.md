# 第六階段：部署、設定與維護

## 架構總覽

```
GitHub Pages（免費）           Supabase（免費方案）
├─ index.html 等公開頁面  ──►  ├─ PostgreSQL：posts、profile、admins（RLS 保護）
├─ admin/ 後台             ──►  ├─ Auth：Email + 密碼，關閉公開註冊
└─ assets/js/config.js          └─ Storage：photos（公開讀、只有管理員能寫）
   （只放 URL + anon key）
```

沒有建置步驟。改完檔案推上 GitHub 就是上線。

---

## 一、第一次上線（需要你本人操作，約 20 分鐘）

### 1. 建立 Supabase 專案
1. 到 <https://supabase.com> 註冊並按 **New project**。
2. Region 選 **Northeast Asia (Tokyo)** 或 **Southeast Asia (Singapore)**。
3. 資料庫密碼請存在密碼管理器（日後不太會用到，但不要遺失）。

### 2. 建立資料表與權限
1. 左側 **SQL Editor → New query**。
2. 打開 `supabase/migrations/20261010000000_init.sql`，全部貼上，按 **Run**。（重複執行不會壞）
3. 再執行一行，把魚魚的 email 加入管理員（**email 要全小寫**）：
   ```sql
   insert into public.admins (email) values ('魚魚的email@example.com') on conflict do nothing;
   ```

### 3. 幫魚魚開帳號、關閉註冊
1. **Authentication → Users → Add user → Create new user**，填魚魚的 email 與密碼（至少 8 碼），勾選 **Auto Confirm User**。
2. **Authentication → Sign In / Providers**：
   - **Allow new users to sign up：關閉** ← 防止陌生人註冊
   - **Email provider：保持開啟** ← ⚠️ 關掉這個會連魚魚都不能登入（本機測試實際踩到過）
3. **Authentication → URL Configuration**：
   - Site URL：`https://<你的帳號>.github.io/<repo名稱>/`
   - Redirect URLs 加入：`https://<你的帳號>.github.io/<repo名稱>/admin/`（「忘記密碼」信件會導回這裡）

> 安全說明：就算有人想辦法註冊了帳號，資料庫只允許「在 `admins` 名單內、且 email 已驗證」的帳號寫入。

### 4. 填入網站設定
**Project Settings → API**（或 **API Keys**），複製：
- Project URL
- **anon / publishable** key（公開用，可以放在網站上）

貼到 `assets/js/config.js`：
```js
export default {
  supabaseUrl: "https://xxxx.supabase.co",
  supabaseAnonKey: "eyJ...（或 sb_publishable_...）"
};
```
**絕對不要**貼 `service_role` / `secret` key。那把鑰匙可以繞過所有權限。

### 5. 上傳到 GitHub Pages
```bash
git init
git add .
git commit -m "魚魚出去玩"
git branch -M main
git remote add origin https://github.com/<你的帳號>/<repo名稱>.git
git push -u origin main
```
GitHub repo → **Settings → Pages** → Source：**Deploy from a branch**，Branch：`main`、資料夾 `/ (root)` → Save。
一兩分鐘後網址是 `https://<你的帳號>.github.io/<repo名稱>/`。

（也可以用 Netlify / Cloudflare Pages：直接把整個資料夾拖上去即可，不需要建置指令。）

### 6. 產生 sitemap（讓搜尋引擎找到文章）
```bash
node scripts/make-sitemap.mjs https://<你的帳號>.github.io/<repo名稱>/
```
再把 `robots.txt` 最後一行的 `# Sitemap:` 改成正確網址並移除 `#`，推上 GitHub。文章變多後可以再執行一次。

> GitHub Pages 的專案網址（`帳號.github.io/repo/`）不在網域根目錄，搜尋引擎不會讀這裡的 robots.txt；
> 可以改到 Google Search Console 直接提交 sitemap.xml。用自訂網域就沒有這個問題。

### 7. 上線後檢查
- [ ] 首頁下方不再出現「示範內容」標籤
- [ ] `/admin/` 用魚魚帳號登入成功
- [ ] 發一篇測試文章（含照片）→ 公開網站看得到 → 刪除
- [ ] 用另一支手機（沒登入）開草稿網址 → 顯示「找不到這篇文章」

---

### 後台入口與安全
- 網站上**沒有**任何連到後台的連結，robots.txt 也不列出後台路徑；魚魚用書籤或加到主畫面的圖示進入。
- 但這只是減少好奇與亂試，**真正的保護是資料庫權限**：只有在 `admins` 名單內、email 已驗證的帳號能寫入，
  就算有人找到 `/admin/`、甚至用別的帳號登入，也讀不到草稿、改不了任何東西（`tests/security.spec.js` 有測試）。
- 建議再加強：魚魚的密碼至少 12 碼且不與其他網站共用；Supabase 後台可開啟 **Authentication → Attack Protection** 的 CAPTCHA 與登入次數限制。

## 二、需要的設定值

| 名稱 | 放在哪 | 公開？ |
| --- | --- | --- |
| Supabase Project URL | `assets/js/config.js` | 可公開 |
| Supabase anon / publishable key | `assets/js/config.js` | 可公開（權限由 RLS 控制） |
| Supabase service_role / secret key | **不放在任何檔案** | 絕不公開 |
| 魚魚的 email | Supabase `admins` 表、Auth 使用者 | — |

## 三、本機開發與測試

需要：Node 22、Python 3、Docker Desktop。

```bash
npm install
npx playwright install chromium webkit
npx supabase start        # 第一次會下載約 2–3 GB 的映像檔
npm test                  # 跑全部測試
npm run dev               # 在 http://127.0.0.1:5500 預覽（未接資料庫＝示範模式）
```

測試內容（2026-10-10 最後一次執行：83 項通過、0 項失敗；另 2 項是手機專用檢查，在桌機設定下自動略過）：

| 檔案 | 測什麼 | 裝置 |
| --- | --- | --- |
| `tests/security.spec.js` | RLS、管理員判斷、草稿保護、Storage 權限、禁止註冊、愛心不能被竄改 | API |
| `tests/admin.spec.js` | 登入失敗、非管理員被擋、上傳照片→草稿→預覽→發布→修改→移除照片→取消發布→刪除、未儲存提醒與恢復、網站設定 | iPhone 14（WebKit）、Pixel 7（Chromium） |
| `tests/public.spec.js` | 讀資料庫、分頁、分類、搜尋、空狀態、網路錯誤重試、燈箱、喜歡、地圖（點選放大、資訊卡、圖釘點擊範圍 ≥ 40px）、減少動態 | iPhone 14、Pixel 7、桌機 |
| `tests/layout.spec.js` | 7 個頁面無水平捲動、手機選單鍵盤操作、觸控目標 ≥ 40px | iPhone SE、Galaxy S9+、iPad、桌機 |

測試帳號由 `tests/global-setup.js` 每次隨機產生，存在 `tests/.local-test-env.json`（已排除於 git）。
測試只會連 `127.0.0.1` 的本機 Supabase，不會碰到正式資料。

截圖在 `tests/screenshots/`，失敗報告用 `npm run test:report` 查看。

## 四、日後維護

| 想做的事 | 怎麼做 |
| --- | --- |
| 魚魚發文、改介紹 | 她自己在 `/admin/` 操作，不需要你 |
| 改顏色、字體、間距 | `assets/css/site.css` 最上方的 `:root` |
| 加分類 | 資料庫 `posts.category` 的 check 條件 ＋ `assets/js/lib/util.js` 的 `CATS` |
| 改資料庫結構 | 在 `supabase/migrations/` 新增一個 SQL 檔，本機 `npx supabase db reset` 測過再到正式環境 SQL Editor 執行 |
| 換 Supabase 專案 | 只要改 `config.js` 兩個值 |
| 備份 | Supabase 免費方案沒有自動備份可下載；建議每月在 **Database → Backups** 或用 `pg_dump` 匯出一次，照片在 **Storage** 可整批下載 |
| 套件升級 | 網站本身沒有 npm 套件；只有 `supabase-js` 用 CDN 固定版本（`data.js` 的 `SUPABASE_ESM`），要升級時改版本號並跑一次測試 |

### 免費方案的限制（2026 年 Supabase 方案，請以官網為準）
- 資料庫 500 MB、檔案空間 1 GB：照片壓縮後每張約 300–600 KB（大圖＋小圖），約可放 2,000 張。
- **一週沒有任何人使用會自動暫停**：網站有訪客就不會。若暫停，到 Supabase 後台按 Restore。

### 已知限制
- 每篇文章分享到 LINE / Facebook 時，預覽卡顯示的是網站共用的圖片與標題（純靜態網站無法為每篇產生）。若之後很在意，可以加一個 Supabase Edge Function 產生預覽頁，不需要重寫網站。
- 離開編輯器時若直接關掉瀏覽器（不是按返回），這次上傳但沒儲存的照片會留在 Storage。不影響網站，只佔一點空間。
- 「喜歡」沒有登入機制，同一個人換瀏覽器可以再按一次。這是刻意的取捨（訪客不需要註冊）。
- 照片壓縮在手機上進行：iPhone 的 HEIC 由 Safari 自動轉檔；少數 Android 瀏覽器無法讀 HEIC，會顯示「這個檔案無法讀取，請改用 JPG」。
