# 第一階段：現況檢查與改造方案

## 1. 檢查結果

| 項目 | 狀態 |
| --- | --- |
| `yuyublog/` | 空資料夾，沒有任何檔案、沒有 git |
| `Traval/`（舊版） | 依使用者要求**不沿用**，只當作「缺什麼」的參考 |
| 本機環境 | Node 22、npm 10、Python 3.11、Git 2.48、Docker Desktop |

舊版（`Traval/`）的架構與缺點，作為新版要避免的事：

- 只有一頁 `index.html`，文章用彈出視窗顯示 → 文章沒有自己的網址，不能被搜尋引擎收錄，分享出去也只能分享首頁。
- 沒有照片時用 SVG 插畫當封面，視覺重心不在攝影。
- 分類只有美食、旅遊、度假，沒有「生活」。
- 文章沒有摘要、沒有圖片說明、沒有餐廳資訊、花費、行程、交通。
- 草稿只是 `published` 開關，沒有發布時間、沒有預覽。
- 照片只存一種尺寸，列表也載入原圖。
- 沒有搜尋、沒有分頁、沒有網路錯誤狀態。
- Supabase 從未設定（`config.js` 空白），沒有任何資料需要搬移。

## 2. 為什麼純前端不夠

只有 HTML / CSS / JavaScript 的靜態網站，**無法單靠前端程式碼**安全地做到：

- **帳號驗證**：密碼檢查寫在前端，任何人打開原始碼就能繞過。
- **文章持久化**：資料只能存在訪客自己的瀏覽器，魚魚發的文別人看不到。
- **圖片管理**：沒有伺服器就沒有地方放照片，也沒有辦法限制誰能上傳。

所以必須搭配一個後端。這裡選 **Supabase**（託管的 PostgreSQL + 登入 + 檔案儲存）。

## 3. 選定的方案

```
訪客瀏覽器 ──► 靜態網站（GitHub Pages / Netlify / Cloudflare Pages，免費）
                 │  HTML、CSS、JS，沒有建置步驟
                 ▼
              Supabase
                 ├─ PostgreSQL：posts、profile、admins
                 │    └─ RLS：訪客只能讀已發布文章；只有管理員能寫
                 ├─ Auth：Email + 密碼登入，關閉公開註冊
                 └─ Storage：photos bucket，公開讀取、只有管理員能上傳/刪除
```

| 面向 | 做法 |
| --- | --- |
| 公開網站 | 多頁靜態網站：首頁、文章列表、文章頁（`post.html?id=`）、旅行足跡、關於魚魚 |
| 管理後台 | `/admin/`，手機優先的單頁應用，Supabase 登入保護 |
| 資料庫 | Supabase PostgreSQL，`supabase/migrations/` 內的 SQL 一次建好所有表格與規則 |
| 圖片 | 瀏覽器端自動壓縮成「大圖 2000px + 小圖 800px」兩種 WebP，再上傳 Storage |
| 權限 | Row Level Security + `admins` 名單；前端只放公開的 anon key，**絕不放** service_role key |
| 部署 | 任何靜態主機皆可；設定只有 `assets/js/config.js` 兩個值 |
| 測試 | 本機用 Supabase CLI + Docker 跑一整套真的 Supabase，用 Playwright 模擬 iPhone / Android 跑完整流程 |

### 為什麼不選 Next.js / 伺服器渲染

| | 靜態 + Supabase（採用） | Next.js + Vercel |
| --- | --- | --- |
| 費用 | 免費 | 免費方案可用，但有用量上限 |
| 維護 | 沒有建置、沒有套件升級壓力 | 要跟著框架版本升級 |
| 部署失敗風險 | 幾乎沒有 | 建置失敗就無法上線 |
| 搜尋引擎 | Google 會執行 JS 後收錄，可接受 | 較佳 |
| 分享到 LINE / FB 的預覽卡 | **每篇都顯示網站共用的預覽圖與標題** | 每篇可顯示自己的封面 |

唯一明顯的代價是「每篇文章自己的分享預覽卡」。如果之後很在意這點，可以只加一個
Supabase Edge Function 產生預覽卡，不需要整個網站重寫。

## 4. 需要你完成的事（無法代辦）

1. 註冊 Supabase 並建立專案（我不能代為建立帳號）。
2. 在 SQL Editor 執行 `supabase/migrations/` 的 SQL，並把魚魚的 email 加入 `admins`。
3. 幫魚魚建立登入帳號、關閉公開註冊。
4. 把 Project URL 與 anon key 填進 `assets/js/config.js`。
5. 推上 GitHub 並開啟 Pages（或拖曳到 Netlify）。

詳細步驟見 `docs/03-部署與維護.md`。
